# 案例入库与模板维护

## 设计原则

案例库是增强项，不是主流程依赖。

没有任何案例时，Skill 仍然使用内置 SOP 生成结果；有案例后，Skill 可以借助案例结构、风格和约束，让输出更贴近你的审美和工作习惯。

## 什么时候入库

看到以下内容时适合入库：

- 优秀的故事版图片 Prompt
- 优秀的视频生成 Prompt
- 结构清晰的广告片分镜
- 动作因果特别清楚的视频提示词
- 参考素材绑定做得好的案例
- 多 Clip 拆分和拼接说明优秀的案例
- 你自己生成后效果不错的 Prompt

## 入库流程

```text
原始案例
→ 判断类型
→ 结构拆解
→ 提取可复用模块
→ 标记不可复用部分
→ 归入模板家族
→ 生成 case card
→ 必要时更新模板库
```

## 自动生成案例卡脚本

```bash
python scripts/scaffold_case.py \
  --raw assets/examples/seedance-sabotage-example.md \
  --name "sabotage action" \
  --family "action-mechanical" \
  --mode video
```

生成后的案例卡需要人工补充拆解结论。脚本只负责生成标准骨架。

## 模板家族维护规则

一个案例只有满足以下条件，才建议沉淀为模板：

1. 结构可以复用到至少 3 个以上未来任务；
2. 不是只靠特殊角色/IP 才成立；
3. 有清晰的版式、节奏或镜头组织方法；
4. 有明确的质量控制点；
5. 能转化为“变量 + 规则”，而不是只能整段复制。

## 不要做的事

- 不要把网上案例原封不动当作万能模板。
- 不要复制特殊 IP、人物、品牌细节作为通用模板。
- 不要把画面风格和叙事结构混在一起不拆解。
- 不要为了扩充案例库而收录低质量案例。

## 建议的长期工作流

每次看到好例子后，先说：

```text
把这个案例入库，拆解它的结构，判断是否适合沉淀成模板。
```

然后再决定：

- 只保存案例卡；
- 提取为 prompt snippet；
- 更新某个 template family；
- 或者作为反面案例记录风险。
